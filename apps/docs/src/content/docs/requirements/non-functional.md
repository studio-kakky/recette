## プラットフォーム

- **モバイル優先のレスポンシブ Web アプリ**
  - 一次デバイス: スマホブラウザ（買い物中・キッチン）
  - 二次デバイス: PC ブラウザ（レシピの登録・整理）
- ネイティブアプリ・PWA 化は MVP ではやらない（PWA は将来検討）

## UI / UX

- 買い物リストは片手・親指操作でチェックできること（タップ領域を大きく）
- レシピ登録は「とりあえず放り込める」ことを優先し、必須項目はタイトルのみ
- 主要操作（一覧 → 詳細 → チェック）が 3G 相当の回線でもストレスなく動くこと

## セキュリティ

- 認証は OAuth のみ。パスワードは保持しない
- 全データはユーザー単位で分離し、API はすべて認可チェックを通す（他人のレシピ・リスト・画像には ID を知っていてもアクセス不可）
- 画像 URL は推測不可能なキー、または署名付き URL で提供する

## 性能・規模の想定

- ユーザー数: 身内規模（〜数十人）
- レシピ数: 1 ユーザーあたり〜1,000 件程度で快適に動けば十分
- 上記規模を超える最適化（キャッシュ戦略・全文検索基盤など）は先送りしてよい

## 運用

- 個人運用のため、ランニングコストは可能な限り低く（無料枠〜数百円/月）
- データのバックアップ手段があること（最低限、定期エクスポートできれば可）
